4. Procedimentos por cenário

Cenário A — Ransomware em BSS/OSS

  1. Isolar VLAN afetada (owner: [___], tempo: ≤15 min)
  2. Desativar contas comprometidas (owner: [___])
  3. Avaliar integridade de backups offline (owner: [___])
  4. Ativar modo degradado: [descrever serviços mínimos]
  5. Notificar CISO e iniciar processo de incidente NIS2
  6. Restaurar de backup após validação forense
  7. Comunicar a clientes se impacto > [___] horas

Cenário B — Destruição de datacenter primário

  1. Confirmar indisponibilidade total do site [___]
  2. Ativar Crisis Manager e equipa BCP
  3. Iniciar failover automático/manual para DC secundário [___]
  4. Validar serviços core em ≤4h (RTO)
  5. Notificar regulador se interrupção > limiar definido
  6. Comunicação pública conforme plano de crise

Cenário C — Falha de fornecedor cloud

  1. Confirmar scope da indisponibilidade (região/AZ: [___])
  2. Ativar failover para região alternativa [___]
  3. Validar portais e APIs em ≤2h
  4. Contactar suporte fornecedor (ticket prioritário)
  5. Comunicar a clientes digitais se > [___] min

Cenário D — Ataque DDoS massivo

  1. Ativar scrubbing center / CDN protection
  2. Contactar upstream providers: [___]
  3. Aplicar blackhole temporário se necessário
  4. Monitorizar serviços core (não devem ser afetados)
  5. Escalar com CSIRT se ataque persistente
